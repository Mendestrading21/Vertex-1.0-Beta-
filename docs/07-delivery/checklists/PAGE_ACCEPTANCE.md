# Checklist d'acceptation d'une page

- [ ] La page répond à sa question principale en moins de 30 secondes.
- [ ] Un seul visuel dominant et un seul bouton primaire maximum.
- [ ] Trois à cinq modules visibles au maximum ; les détails sont progressifs.
- [ ] Contrat API exact, sans calcul financier TypeScript.
- [ ] Source, qualité, couverture, fraîcheur, unité et timezone visibles.
- [ ] `loading`, `refreshing`, `empty`, `partial`, `delayed`, `stale`, `offline`, `error` validés.
- [ ] Une absence n'est jamais affichée comme zéro.
- [ ] Les données de démonstration, estimées, théoriques et réelles sont distinctes.
- [ ] Navigation clavier, lecteur d'écran, focus et contraste validés.
- [ ] Alternative tabulaire ou textuelle pour tout graphique essentiel.
- [ ] 1280×800, 1440×900 et 1600×1000 passent les tests visuels desktop.
- [ ] 1024×768 passe le test de dégradation laptop sans masquer vérité financière, provenance, alerte ou action essentielle.
- [ ] Aucun viewport téléphone n'est un gate Beta ; mobile reste `LATER` sur les contrats canoniques.
- [ ] Budgets LCP, INP, CLS et bundle respectés.
- [ ] Unitaires, composants, contrats, visuels et E2E passent.
- [ ] Télémétrie utile sans secret, portefeuille ou cardinalité ticker non bornée.
